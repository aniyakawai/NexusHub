    Knowledge Base¶

    An enterprise-owned professional knowledge base containing various types of data. It supports creating and managing knowledge bases, providing a source of knowledge for Q&A conversations and powering intelligent Q&A.

    • Shared knowledge base: after the System Administrator creates a share in [Shared Resources], it can be authorized to specified workspaces.
    • All knowledge bases: users can create knowledge bases. Other users can view, use, and maintain them after Resource Authorization.

    Knowledge bases are managed through folders. Up to three levels of subfolders can be created under the root directory. Corresponding knowledge bases can be created in each level of folder. Folders support resource authorization. Regular users can only view authorized folders, and when authorizing a folder, the existing sub-resources under the folder can also be authorized.

    Note: Shared Resources is an X-Pack feature of the Enterprise Edition.

    1 Create Knowledge Base¶

    Open the [Knowledge Base] page and click [Create Knowledge Base] to enter the Create Knowledge Base page.
    Knowledge base type:

    • General knowledge base: Manages the upload of offline documents. The supported text document formats include Markdown, TXT, PDF, DOCX, and HTML, as well as QA pairs in Excel and CSV formats.
    • Web Site Knowledge Base: used for online static text data management. After entering a Web Root Address, it automatically syncs the text data of the root address and its subordinate addresses.
    • Feishu Knowledge Base: Supports connecting to Feishu cloud documents and spreadsheet documents, and importing Feishu document content into MaxKB for management.
    • Workflow Knowledge Base: allows users to freely orchestrate the entire process from different data sources to writing into the knowledge base by dragging and dropping nodes, meeting the individualized knowledge management needs of enterprises.

    Note: The Feishu knowledge base is an X-Pack feature; for specific usage, refer to Feishu Document.

    1.1 General Knowledge Base¶

    Select the knowledge base type as general, enter the knowledge base name and description, and select an embedding model.

    After creating a knowledge base, you can create new documents and upload offline documents.

    Note: Chat User is an X-Pack feature.

    Offline documents can be uploaded by dragging and dropping or by selecting files. Document upload requirements:

    • Text files: Markdown, TXT, PDF, DOCX, HTML, XLS, XLSX, CSV, ZIP;
    • Tables: XLS, XLSX, CSV, ZIP;
    • QA Q&A pairs: XLS, XLSX, CSV, ZIP;
    • By default, up to 50 files can be uploaded at once, with each file not exceeding 100 MB. This is configurable: the maximum number of uploaded files is 1000, and a single document is up to 1000 MB;
    • Supports selecting a folder and uploading the files under it that meet the requirements.

    • ZIP files come in two forms:

      • Markdown document + image files: reference the corresponding images in the Markdown document and package both in a ZIP.
      • XLS/XLSX files + image files: reference the corresponding images in the XLS/XLSX files and package both in a ZIP.

    Document segmentation:

    • Select Segmentation Rules supports two segmentation methods: Intelligent Segmentation and Advanced Segmentation:

      • Intelligent Segmentation: segments hierarchically by Markdown format (up to 6 heading levels), with a maximum of 4096 characters per segment;
      • Advanced Segmentation: Supports customizing the segment identifier, segment length, and automatic cleaning. Segment identifiers also support using regular expressions to process documents with complex structures.

    • Add segment titles as associated questions upon import: When checked, the titles of all segments will be set to the segments' associated questions.

    • Preview: View the segmentation effect based on the segmentation rules and settings.

    • Segment Operations: In the segment preview, re-edit unreasonable segments and delete meaningless segments.
    • Step Operations: You can go back to the previous step to re-upload the document, or confirm the upload to start vectorization.

    Intelligent Segmentation and Advanced Segmentation:

    Intelligent Segmentation:

    • Intelligent Segmentation Rules for MarkDown Files

      • Hierarchical segmentation by heading (up to 6 heading levels), with a maximum of 4096 characters per segment;
      • When the character count of the lowest-level text paragraph exceeds the configured segment length, the system looks for a line break within the segment length to truncate the text.

    • Intelligent Segmentation Rules for HTML and DOCX Files

      • Recognize heading formats and convert them to Markdown heading styles;
      • Segment by drilling down level by level (up to 6 levels of headings), with each segment up to 4096 characters.

    • Intelligent Segmentation Rules for TXT and PDF Files

      • Segments are split by the heading #; if there is no # heading, the text is split by 4096 characters.
      • Find a line break within the segment length and truncate there.

    Advanced Segmentation:

    • Supported segment identifiers: #, ##, ###, ####, #####, ######, -, blank line, carriage return, space, semicolon, comma, and period. You can also manually enter other segment identifiers or Regular Expression.
    • Segment length: the length of a single segment, ranging from 50 to 4096 characters.
    • Auto Clean: When enabled, the system automatically removes duplicate and redundant symbols such as spaces, blank lines, and tabs.
    • Documentation Standards Suggestions:
      • Marker conventions: the segment markers of offline documents should follow a certain convention; otherwise the split segments will be irregular.
      • Paragraph completeness: describe one complete piece of content within a single segment.

    Add segment titles as associated questions upon import: When checked, the titles of all segments will be set to the segments' associated questions.

    After clicking 【Start Import】, the system backend will perform auto segmentation -> storage -> vectorization on the documents; when processing finishes, the file status will show as Completed.

    1.2 Web Site Knowledge Base¶

    Select the knowledge base type as Web site, enter the knowledge base name and description, select an embedding model, and enter the Web root address.

    • Web Root Address: the root node address of the online static website. The system automatically retrieves data from the web root address and its subordinate addresses. Taking the DataEase V2 online documentation as an example, the Web Root Address can be: https://dataease.io/docs/v2/.
    • Selector: For Web page data, you can specify to retrieve data within a certain div; by default the body data is retrieved. For example, to retrieve only the middle content of the DataEase online documentation, you can right-click to inspect the page, locate the middle inner region and find the div named md-content, then the selector input is: .md-content .

    After clicking 【Create】, you are redirected to the document list page to view the details of the documents under the current Web site; when processing finishes, the file status will show as Completed.

    1.3 Workflow Knowledge Base¶

    Supports users independently orchestrating the full process from different data sources to knowledge base writes through node dragging, adapting to enterprises' personalized knowledge management needs.

    Select the knowledge base type as workflow knowledge base, enter the knowledge base name and description, and select an embedding model.

    1.3.1 Workflow Orchestration¶

    The basic flow of knowledge base workflow orchestration: data source -> document parsing -> document segmentation -> knowledge base write.

    Data Source:

    • Note: The start node of the workflow, responsible for obtaining raw data. Users only need to develop data source tools according to the standard to connect to the workflow, without waiting for system version updates.
    • Settings:
      • Built-in data sources: supports local files and Web sites;
      • Tool Extension: supports data source tools to access other enterprise-level data sources.

    Document Parsing:

    • Note: Convert raw data into plain text or structured text. Users can develop parsing tools according to the standard to connect to the workflow, without waiting for system version updates.
    • Settings:
      • Supports automatic parsing of mainstream formats such as TXT, Markdown, DOCX, XLSX, CSV, PDF, and ZIP.
      • Supports integrating other parsing tools through tools, such as OCR tools, MinerU, and other professional parsing tools.

    Document Segmentation:

    • Note: Split long text into retrievable units based on semantics or rules.
    • Settings: Supports segmenting/non-segmenting for storage and referencing third-party segmentation tools.
      • Segmentation and storage:
        • Intelligent Segmentation: segments hierarchically by Markdown format (up to 6 heading levels), with a maximum of 4096 characters per segment;
        • Advanced Segmentation: Supports customizing the segment identifier, segment length, and automatic cleaning. Segment identifiers also support using regular expressions to process documents with complex structures.
        • QA Q&A pair segmentation: extract "question-answer" pairs for ingestion.
      • Importing without segmentation: delete the “Document Segmentation” node to import documents without segmentation.
      • Independently introduce third-party segmentation tools to adapt to complex content splitting needs.

    Knowledge write:

    • Note: The end node of the workflow, which completes data persistence and vectorization.
    • Settings: After passing through nodes such as document parsing and document segmentation, the content will be automatically written to the knowledge base and vectorization will be performed.

    1.3.2 Debug and Publish¶

    After orchestration is complete, click the [Debug] button on the interface, and the system will execute the Workflow according to the flow.

    In 【Execution Details】, users can view the running status of each node, such as whether the data source successfully retrieved the document, whether the parsing tool correctly extracted the content, whether the segmentation result meets expectations, and whether the write was successful.

    After debugging without errors, click [Publish] to make this workflow take effect.

    1.3.3 Import Document¶

    After the workflow is published, users can perform the Import Document operation in the document list. Import Document is the same as the Debug feature on the workflow page.

    1.3.4 Other Operations¶

    Template Center

    In a workflow knowledge base, you can directly select the desired knowledge base workflow in the 【Template Center】. You only need to configure basic parameters such as the model and knowledge base in the orchestration interface to quickly complete the workflow deployment of the knowledge base and realize the intelligent implementation of typical business scenarios.

    To enrich template resources and drive the sustainable development of the product ecosystem, MaxKB sincerely invites community users to participate in building the Template Center and share technical achievements;

    Contribution path: Refer to the template development guidelines provided by the official team to develop agent or knowledge base workflow templates for MaxKB;

    Submission method: After development is complete, submit the template to GitHub Official Repository. The project team will review it according to the process, and once approved it will be listed on the MaxKB Template Center for all community users to use.

    Import/Export Workflow

    The workflow knowledge base supports export and import. The exported file has the extension .kbwf; to import a workflow, select a file with the corresponding extension.

    Execution Record

    Each document import operation is recorded in the workflow's 【Execution Records】; users can search for specific execution records by initiator or status, enabling full-chain traceability of all import operations.

    Release History

    In the workflow knowledge base, you can view information such as the workflow, time, and user of published historical versions.

    Auto Save

    In the workflow knowledge base, manual saving is the default; automatic saving can also be enabled. Once automatic saving is enabled, the configuration is saved to the local machine every minute and synced to the backend database after a successful publish.

    2 Knowledge Base Operations¶

    MaxKB knowledge bases support sync, re-vectorization, question generation, resource authorization, viewing associated resources, transfer to, settings, export, and delete operations.

    2.1 Synchronize Web Knowledge Base¶

    For a Web site-type knowledge base, click [Sync] in the knowledge base panel to synchronously update the content of the Web knowledge base.

    • Synchronize & Replace: re-fetch the documents from the web site and overwrite the documents in the local knowledge base.
    • Full sync: First delete all documents in the local knowledge base, then re-fetch the Web site documents.

    2.2 Re-vectorization¶

    If a different embedding model is selected in the knowledge base settings, newly added documents will be vectorized using the newly configured embedding model. To re-vectorize an existing knowledge base, click [Re-vectorize] in the knowledge base panel in the knowledge base card grid to re-vectorize the existing segments in the knowledge base.

    2.3 Generate Questions¶

    Use an AI model (with configurable model parameters) to summarize the file content based on the prompt and generate corresponding questions, which are automatically associated with segments.

    2.4 Resource Authorization¶

    Click 【Resource Authorization】 on the knowledge base panel to authorize the knowledge base to the corresponding users.

    2.5 View Associated Resources¶

    In the knowledge base list, click 【View Associated Resources】 on the knowledge base panel to view the resources associated with the knowledge base. You can search by name, creator, and type.

    • Dependencies: view the other resources on which the current resource depends (agent, model, knowledge base, tool);
    • Depended on: view which other resources (Agent, model, knowledge base, tool) depend on the current resource.

    2.6 Move to¶

    In the knowledge base list, click 【Move To】 on the knowledge base panel to move the knowledge base to another folder of tools under the same workspace.

    2.7 Set Knowledge Base¶

    In the knowledge base list, click 【Settings】 on the knowledge base panel to enter the knowledge base settings page, where you can modify the basic information of the knowledge base (name, description, embedding model) and the upload rules: the maximum number of files per upload and the maximum size of a single document (MB).

    2.8 Export Documents Excel/ZIP¶

    In the knowledge base list, click 【Export Excel】/【Export ZIP】 on the knowledge base panel to export the segments of the knowledge base in Excel or ZIP file format.
    Each document is one Sheet in the Excel file, and each row in the Sheet displays one segment. When exporting as a ZIP file, the referenced images are exported together, named by guid, without format extensions.

    To import a document Excel/ZIP knowledge base, first create a General Knowledge Base, click [Upload Document], select [QA Pair], upload the documents exported from the knowledge base, and click [Start Import].

    2.9 Export Knowledge Base¶

    Supports exporting all metadata of a knowledge base (documents, tags, questions, workflows) and their associations, supporting cross-environment migration and batch reuse; the exported file extension is .zip.

    Click 【Create】 -> 【Import & Create】, select the exported knowledge base file, and open it.

    2.10 Delete Knowledge Base¶

    In the knowledge base list, click 【Delete】 on the knowledge base panel to delete the knowledge base.

    Note: A knowledge base cannot be recovered after deletion. Please proceed with caution.

    3 Batch Selection¶

    Click batch selection to select multiple knowledge bases for move or delete operations.
