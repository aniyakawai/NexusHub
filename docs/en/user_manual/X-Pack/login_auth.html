    Login Authentication¶

    Login Settings¶

    MaxKB supports configuring the default login method and the account login verification code.

    Login Method: administrators can freely choose and enable the most suitable login method based on the identity authentication strategy and security management requirements of the enterprise.

    Default login method: Administrators can pre-set the system’s default login method according to the enterprise’s unified login policy, such as account-password login or third-party login.

    Account login verification code settings: When a user's consecutive login failures reach the preset threshold, the system automatically triggers the verification code mechanism and the account-lock function after failed logins, effectively preventing security risks such as brute-force attacks.

    Default role assignment for third-party users: the default workspace and role assigned by default to users who log in via third-party accounts, for unified management of third-party users.

    Login Authentication¶

    Supports LDAP, CAS, OIDC, OAUTH2, and SAML2 single sign-on authentication protocols, as well as QR-code login and passwordless login on the mobile end for WeCom, DingTalk, and Feishu, meeting enterprises' needs for strong authentication and access control.

    6 Scan to Log In¶

    Supports WeCom, DingTalk, and Feishu integration, as well as QR-code login and passwordless login.

    6.1 Connecting WeCom¶

    6.1.1 WeCom Connection Settings¶

    To connect MaxKB to WeCom, fill in the following information:

    • Corp ID: the enterprise ID. Obtained by the WeCom administrator under [Enterprise Information] in the management console.
    • Agent ID: the unique ID of the WeCom self-built application, obtained when the WeCom administrator creates or views the application in the management console.
    • App Secret: the secret of the WeCom self-built application.
    • Callback address: the URL used to access MaxKB.

    When configuring WeCom QR-code login for MaxKB, the WeCom administrator needs to log in to WeCom Management and create an enterprise self-built application, then publish the application after completing the configuration.

    Step 1: Create an application. In [App Management - Apps - Self-Built], click [Create App], enter the application name and other information. Once the app is created, you can view the application's Agent ID and Secret.

    Step 2: Set the trusted domain. In [Developer Interface], click [Set Trusted Domain], add a trusted domain, and verify it. See Trusted Domain Configuration.

    Step 3: Authorize the callback domain. In [WeCom Authorization], set the authorization callback domain.

    Step 3: Configure the enterprise trusted IP. In [Enterprise Trusted IP], configure the trusted IP.

    After configuring and publishing the WeCom application, configure the corresponding information on the MaxKB WeCom login QR code configuration page and pass the verification.

    Afterwards, you can click WeCom on the MaxKB login page to log in by scanning the QR code.

    6.1.2 WeCom Password-Free Login Settings¶

    For constructing the app homepage URL, refer to the WeCom development guideCreate a web authorization link — construct an enterprise OAuth2 link.
    The link format and parameter descriptions are as follows:

    • Link format: https://open.weixin.qq.com/connect/oauth2/authorize?redirect_uri=REDIRECT_URI/admin/api/wecom/oauth2&response_type=code&scope=snsapi_privateinfo&appid=CorpID&agentid=AgentID&state=maxkb#wechat_redirect
    • CORPID: the CorpID of the enterprise
    • REDIRECT_URI: the callback link address redirected to after authorization. The link needs to be processed with urlencode, for example: https%3A%2F%2Fmaxkbk.fit2cloud.cn. Just adjust the domain part.
    • SCOPE: just fill in snsapi_privateinfo
    • AGENTID: the application ID

    Example home page address: https://open.weixin.qq.com/connect/oauth2/authorize?redirect_uri=https%3A%2F%2Fmaxkbk.fit2cloud.cn/admin/api/wecom/oauth2&response_type=code&scope=snsapi_privateinfo&appid=ww5fad05aaa36d118c&agentid=1000002&state=maxkb#wechat_redirect

    After the configuration is complete, find the MaxKB application in the WeCom workbench and access MaxKB without login.

    6.2 Connecting DingTalk¶

    6.2.1 DingTalk Connection Settings¶

    To connect MaxKB to DingTalk, fill in the following information:

    • Corp ID: the DingTalk organization ID; view it in the organization information at the top right of the DingTalk open platform.
    • APP Key: the DingTalk application ID; view it under the application's [Credentials and Basic Information] in the DingTalk open platform.
    • App Secret: the DingTalk application secret; view it under the application's [Credentials and Basic Information] in the DingTalk open platform.
    • Callback address: the URL used to access MaxKB.

    When configuring DingTalk QR-code login for MaxKB, you need to create and configure an application in DingTalk Open Platform.

    Step 1: Create an application. In [App Development - DingTalk App], click [Create App]. After the app is created, you can view the APPKey and APPSecret information in [Credentials & Basic Information].

    Step 2: Permission settings.

    • Go to [Permission Management] and add the permissions shown in the figure below.

    • Also add the authorized callback domain in the 【Callback Domain】 under 【Share Settings】, noting that the domain must match the 【Callback Domain】 filled in on the MaxKB platform.

    • Also add the authorized callback domain in the 【Redirect URL】 under 【Security Settings】, and ensure the domain name is consistent.

    Step 3: In [Version Management & Publishing], fill in the application version number and version description, then click [Save] to publish the application.

    After completing the configuration, publish it, then configure and save it on the MaxKB DingTalk QR code login configuration page.

    Afterwards, you can click DingTalk on the MaxKB login page to log in by scanning the QR code.

    6.2.2 DingTalk Password-Free Login Settings¶

    Add the web application capability. In the 【Application Capability】 of the DingTalk open platform, add 【Web Application】.

    Set [App Home Page] and [PC Home Page URL].

    The address format is: http(s)://xxx.xxx.xxx/admin/login?client=dingtalk=CORPID. Note that corpId=CORPID must be replaced with the actual CORPID.

    Security Settings. In 【Security Settings】, set the redirect URL and the in-app login-free address.

    Share Settings: in 【Access Login】, set the 【Callback Domain】.

    After the app is published, you can access MaxKB from the DingTalk workbench without logging in.

    6.3 Connecting Feishu¶

    6.3.1 Feishu Connection Settings¶

    To connect MaxKB to Feishu, fill in the following information:

    • APP Key；
    • Corp ID；
    • App Secret: the callback address provided by MaxKB, which also serves as the redirect address for Feishu login-free authorization;
    • Callback address: the MaxKB URL address plus '/api/feishu', for example: http://xx.xxx.xx.xxx/api/feishu.

    When configuring Feishu QR-code login for MaxKB, you need to create an enterprise self-built application in Lark Open Platform, publish it after completing the configuration, and then configure and save it on the MaxKB Feishu QR-code login configuration page.

    Step 1: Create an enterprise self-built application. Click [Create Enterprise Self-Built Application], enter the application name and description, upload an application icon, then click [Create].

    Step 2: Permission configuration

    • Configure the redirect URL. In [Development Configuration - Security Settings], enter the callback address in the MaxKB Feishu QR-code configuration dialog, and click [Add].

    • Application authorization: authorize the application in the Permission Management of the application. Refer to the following figure for the specific permissions:

    Step 3: Publish the application. In [Version Management & Publishing], enter the application version number and update notes, then click [Save] to complete the application publishing.

    After publishing the app, you can click Feishu on the MaxKB login page to log in by scanning the QR code.

    6.3.2 Feishu Password-Free Login Settings¶

    Add the 【Page Application】 capability.

    Configure the desktop home page. For example, enter the desktop home page address in the configuration, such as: http(s)://xxx.xxx.xxx/admin/login?client=lark&appId=cli_a7e1c1ddexxxxx.

    Add the redirect URL in 【Security Settings】.

    After the app is published, you can access MaxKB from the Feishu workbench without logging in.
