    Resource Authorization¶

    The Resource Authorization feature is used to manage users' access permissions to resources within a workspace.

    • System Administrators can authorize all resources in [System Management];
    • Workspace administrators can grant access to all resources in the workspace;
    • Regular users can authorize the resources they create.

    1 System Resource Authorization¶

    System Administrators (all workspaces) and Workspace Administrators (who can only select workspaces where they have the Workspace Administrator role) can perform resource authorization operations:

    • Member: lists the members under the selected workspace who are Regular Users or inherit the Regular User role.
    • Resources: Agents, knowledge bases, tools, and models list the resources under the selected workspace by the folder management directory of the workspace.
    • Operation:
      • No authorization: no authorization is granted to resources by default.
      • View: You can only view and use the resource, and cannot add, delete, or modify it.
      • Manage: allows all operations on the resource.
      • By user role: for the selected resources, grant users the permissions owned by the role.

    Note: Features such as Workspace and Role Management are X-Pack features.

    2 User Resource Authorization¶

    Users can authorize resources to specified users in agents, knowledge bases, tools, and models. The authorized users are all members of the current workspace. Resource authorization supports filtering by name, username, permission, and role; after filtering, permissions can be configured in batch.

    Note: User roles are an X-Pack feature.

    3 Resource Authorization Rules¶

    • By default, authorization to the system administrator is granted by user role; changing the workspace administrator and the system administrator does not affect either’s role permissions over resources (high priority);
    • When a Regular User is granted the [Manage] permission, they can also perform resource authorization operations on agents, but must follow the rule that role permissions take precedence;
    • If a member has multiple roles, the authorization is based on the maximum permissions (the union) of all roles.
